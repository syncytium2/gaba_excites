# Pospischil et al. 2008 — the pyramidal cell and the fast-spiking interneuron, via ModelDB 123623

The parameters come from the model's code, not from the paper's text: the
ModelDB cell is the one with runnable mechanisms to check against, and it
differs from some in-vitro fits described in the paper.

Source: github.com/ModelDBRepository/123623 at commit `8dfc13f`.

## `sPY_template`

```
diam = 96, L = 96          "so that area is about 29000 um2"   → π·96² = 28 953 µm² → 289.53 pF
cm = 1
insert pas   e_pas = -70,  g_pas = 0.0001          "Rin = 34 Meg"
insert hh2   ek = -100, ena = 50, vtraub_hh2 = -55
             gnabar_hh2 = 0.05, gkbar_hh2 = 0.005
insert im    taumax_im = 1000, gkbar_im = 7e-5
celsius = 36 (demo_PY_RS.hoc)
```

The template's "Rin = 34 Meg" is the leak alone. With the channels open at
rest included, the input resistance at rest (−70.57 mV) is **32.13 MΩ**, which
is what the app measures at its default leak (g_pas × area = 28.95 nS).

## `sIN_template` (the fast-spiking interneuron)

```
diam = 67, L = 67          "so that area is about 14000 um2"   → π·67² = 14 103 µm² → 141.03 pF
cm = 1
insert pas   e_pas = -70,  g_pas = 0.00015          "Rin = 48Meg"
insert hh2   ek = -100 (v_potassium), ena = 50 (v_sodium), vtraub_hh2 = -55
             gnabar_hh2 = 0.05, gkbar_hh2 = 0.01     "spike duration of interneurons"
(no im)
celsius = 36 (demo_IN_FS.hoc)
```

The same two mechanisms as the pyramidal cell: twice the K⁺ density and no M
current. With the channels open at rest included, Rin at rest (−70.00 mV) is
**47.3 MΩ**, against the comment's 48; the leak is g_pas × area = 21.15 nS.

## `HH_traub.mod` (hh2), with v2 = v − vtraub

```
αm = 0.32·vtrap(13 − v2, 4)     βm = 0.28·vtrap(v2 − 40, 5)
αh = 0.128·exp((17 − v2)/18)    βh = 4/(1 + exp((40 − v2)/5))
αn = 0.032·vtrap(15 − v2, 5)    βn = 0.5·exp((10 − v2)/40)
vtrap(x, y) = x/(exp(x/y) − 1)
tadj = 3^((celsius − 36)/10) = 1 at 36 °C
states advanced exactly at fixed v:  x ← x + (1 − exp(−dt/τ))(x∞ − x)
```

## `IM_cortex.mod`

```
m∞ = 1/(1 + exp(−(v + 35)/10))
τ  = taumax / (3.3·exp((v + 35)/20) + exp(−(v + 35)/20))
tadj = 2.3^((celsius − 36)/10) = 1 at 36 °C
```

## The oracle

`tools/neuron_oracle.py` compiles these two .mod files in NEURON 9.0.2, runs
the published cell (3 s settle, 800 ms steps, dt = 0.01 ms, implicit Euler),
and writes `src/core/oracle/neuron_rs.json`. Spike counts match exactly at
500–1500 pA; every spike time agrees within 0.20 ms.

`tools/neuron_oracle.py <dir> fs` does the same for `sIN_template` and writes
`neuron_fs.json` (checked 2026-10-15, same NEURON and commit, and the
pyramidal reference regenerated byte-identically first). Spike counts match
exactly at 250–3200 pA, 526 spikes up to 298 Hz; every spike time agrees
within 0.015 ms.

## `sPYr_template` with `demo_PY_LTS.hoc` (the LTS cell)

The template is the cell's skeleton; `demo_PY_LTS.hoc` then overrides six
values "for bursting behavior". The app uses the demo's values, which are the
ones the template's header ties to Destexhe, Contreras & Steriade 2001.

```
sPYr_template                       demo_PY_LTS.hoc overrides
diam = 96, L = 96  → 289.53 pF      (same sphere as sPY_template)
insert pas   e_pas = -70            e_pas = -85
             g_pas = 1e-5           g_pas = 1e-5      → 2.895 nS
insert hh2   ek = -100, ena = 50, vtraub_hh2 = -55
             gnabar_hh2 = 0.05      gnabar_hh2 = 0.05
             gkbar_hh2 = 0.005      gkbar_hh2 = 0.005
insert im    taumax_im = 1000
             gkbar_im = 3e-5        gkbar_im = 3e-5
insert cad   depth_cad = 1 (um), taur_cad = 5 (ms), cainf_cad = 2.4e-4 (mM), kt_cad = 0
insert it    cai = 2.4e-4, cao = 2 (mM), eca = 120 (unused: it computes its own)
             gcabar_it = 0.001      gcabar_it = 4e-4  → 0.4 mS/cm²
celsius = 36, v_init = -84 (demo)
```

The demo's own comment gives the other regimes from the same cell: e_pas −75
with 0.12 nA for regular spiking, e_pas −60 with −0.075 nA for LTS, e_pas −85
with 0.15 nA for bursting. The app keeps −85 and lets the holding current
move the cell instead: 60 pA holds it at −64 mV, where it rebounds.

## `IT_huguenard.mod` (Destexhe 1993, modified 1995)

"Model based on the data of Huguenard & McCormick, J Neurophysiol 68:
1373-1383, 1992 and Huguenard & Prince, J Neurosci. 12: 3804-3817, 1992." The
equations below are the .mod file's; they were not checked against either
paper.

```
I     = gcabar · m_inf² · h · (v − carev)
carev = 1e3 · R·(celsius + 273.15) / (2F) · ln(cao/cai)       mV
Vm    = v + shift,  shift = 2 mV ("corresponds to 2mM ext Ca++")
m_inf = 1 / (1 + exp(−(Vm + 57)/6.2))                         instantaneous
h_inf = 1 / (1 + exp((Vm + 81)/4))
tau_h = (30.8 + (211.4 + exp((Vm + 113.2)/5)) / (1 + exp((Vm + 84)/3.2))) / phi_h
phi_h = q10^((celsius − 24)/10),  q10 = 3                     = 3.737 at 36 °C
INITIAL h = 0
```

R and F come from the file's UNITS block, which NEURON 9 resolves to the 2019
SI values (R = 8.31446261815324, F = 96485.33212331001); the port uses those.
m_inf is computed in the state block, so the current uses the value from the
last state update; the port keeps m in the state vector for the same reason.
`INITIAL h = 0` does not matter after the 3000 ms settle on either side.

## `cadecay_destexhe.mod` (Destexhe 1995)

```
drive = −10000 · ica / (2 · FARADAY · depth),  FARADAY = 96489 (its own CONSTANT)
if drive ≤ 0: drive = 0                    "cannot pump inward"
cai'  = drive + (cainf − cai) / taur       SOLVE … METHOD derivimplicit
```

ica in mA/cm², cai in mM, depth in µm. The app keeps calcium in µM and
current in pA, so with ica = I(pA)·10⁻³/Cm(pF) at 1 µF/cm², the drive is
−10⁴·I / (Cm · 2F · depth) µM/ms (`src/core/pools.ts`). derivimplicit on this
linear equation is backward Euler, done in closed form; the pool integrates
the ica of the start of the step, as NEURON does (nrn_cur before the solve,
nrn_state after it).

## The LTS cell as built

Rest −83.95 mV, Rin at rest 446.2 MΩ (leak alone: 345 MΩ); 60 pA holds it at
−63.95 mV, Rin 184 MΩ. All pinned in `src/core/lts.test.ts`; the spike times
in `src/core/oracle.test.ts` against `tools/neuron_oracle.py lts`.

`tools/neuron_oracle.py <dir> lts` (2026-10-21, NEURON 9.0.2, the same commit,
the pyramidal and fast-spiking references regenerated byte-identically first)
runs four families of 500 ms steps, each settled 3 s at its own holding
current: depolarizing steps from rest (0 pA), and hyperpolarizing ones held at
60, 50 and 30 pA. Spike counts match exactly on all 12 sweeps, bursts and
rebounds alike; every spike time agrees within 0.010 ms.
